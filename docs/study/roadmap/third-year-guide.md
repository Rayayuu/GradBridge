# 大三应该做什么

> 大三最重要的事情，是开始把过去两年的积累转换成真实的求职结果。

很多学生到了这一阶段才发现：

- CV 需要时间修改
- LeetCode 不能一周突击
- 项目需要能讲，而不是只存在 GitHub
- Behavioral Interview 也需要准备
- 招聘开放时间可能比想象中早

因此，大三的关键词是：

**系统化求职。**

---

## 大三结束时，你应该达到什么状态

- CV 可以随时投递
- 有 2–4 个能够深入讲解的项目
- LeetCode 常见模式基本覆盖
- 能完成 Technical Interview
- 有 Behavioral 故事库
- 有自己的 Job Tracker
- 经历过真实 OA / Interview
- 对 Graduate / Internship 招聘流程比较熟悉

---

## 第一件事：把求职当成项目管理

不要只靠记忆。

建议建立一个长期 Job Tracker。

至少记录：

| 字段 | 示例 |
| --- | --- |
| Company | Example Tech |
| Role | Software Engineer Intern |
| Location | Sydney |
| Applied | 2026-xx-xx |
| Status | OA |
| Deadline | Official career page |
| Next Step | Prepare coding test |

每周固定检查一次。

---

## 第二件事：把 CV 变成招聘工具

大三的 CV 不应该只是“个人经历汇总”。

它需要帮助 Recruiter 快速判断：

> 你是否值得进入下一轮？

每条经历尽量体现：

```text
Action
+
Technical Detail
+
Impact
```

例如项目中可以说明：

- 构建了什么
- 使用什么技术
- 你负责哪部分
- 解决什么问题
- 性能或结果有什么变化

同时要避免：

- 一整段没有重点
- 只列技术栈
- 每个项目描述完全一样
- 写大量无法验证的夸张结果

---

## 第三件事：LeetCode 从题目变成 Pattern

大三不能再只随机刷题。

需要形成题型体系。

建议至少覆盖：

```text
Array / String
HashMap
Two Pointers
Sliding Window
Stack / Queue
Linked List
Binary Search
Tree
Heap
Graph
DFS / BFS
Backtracking
Dynamic Programming 基础
```

每做一道题都可以问：

1. 这是哪个 Pattern？
2. 为什么这个方法成立？
3. Complexity 是多少？
4. 有没有更好的方法？
5. 面试时我能不能边说边写？

---

## 第四件事：系统准备 Technical Interview

算法只是技术面试的一部分。

常见基础范围可能包括：

- OOP
- Database
- Operating Systems
- Networking
- HTTP
- REST
- Authentication
- Cache
- Concurrency
- Testing
- Git

如果你走 Backend，还应该逐渐理解：

- Session vs JWT
- Index
- Transaction
- Redis
- API Design
- Load Balancing 基础
- Message Queue 基础
- System Design 基础

如果你走 AI，则需要进一步准备：

- Model Evaluation
- Overfitting
- Training Pipeline
- Feature / Data Processing
- Deployment
- 推理性能
- 项目中的模型选择

---

## 第五件事：项目必须讲深

面试官通常不会满足于：

> “这个项目用了 Spring Boot。”

他们可能继续问：

- 为什么使用 Spring Boot？
- Authentication 怎么做？
- Database Schema 怎么设计？
- 出现过什么 Bug？
- 最大瓶颈是什么？
- 如果用户量增加十倍怎么办？

因此，每一个核心项目都建议准备一份自己的 Project Deep Dive。

结构可以是：

```text
Problem
→ Architecture
→ My Contribution
→ Technical Challenge
→ Decision
→ Result
→ What I Would Improve
```

---

## 第六件事：建立 Behavioral 故事库

Behavioral 不适合完全临场发挥。

建议至少准备这些主题：

- Leadership
- Conflict
- Failure
- Tight Deadline
- Difficult Technical Problem
- Team Collaboration
- Learning Something Quickly
- Receiving Feedback

每个故事按照 STAR 整理：

```text
Situation
Task
Action
Result
```

真正重要的是 Action。

因为面试官想知道的是你具体做了什么。

---

## 第七件事：真实面试本身也是训练

第一次 OA 或面试表现不理想很正常。

每次结束后都应该复盘。

例如记录：

- 哪些问题没答好
- 哪个知识点不会
- 哪道算法题卡住
- 项目哪个部分讲不清
- Behavioral 哪个故事不够好

然后把这些反馈加入下一轮准备。

这会形成：

```text
申请
→ 面试
→ 复盘
→ 补强
→ 再申请
```

---

## 第八件事：Networking 开始发挥作用

Networking 不等于到处找陌生人要 Referral。

更自然的方式包括：

- Career Fair
- Tech Event
- University Society
- Alumni
- LinkedIn
- Hackathon
- Open-source Community

目标是逐渐理解行业、岗位和团队。

而不是把每一次交流都变成“可以内推我吗”。

---

## 大三如何判断自己的求职问题

可以看你的招聘漏斗。

### 大量投递，但没有 OA

优先检查：

- CV
- 岗位匹配度
- Eligibility
- Timing

### 有 OA，但没有 Interview

优先检查：

- Coding
- Algorithm
- Online Assessment

### 有 Interview，但没有 Offer

优先检查：

- Technical Depth
- Communication
- Project
- Behavioral

不要所有问题都用“继续海投”解决。

---

## 大三最常见的错误

### 求职准备和投递完全分开

最有效的状态通常是边准备、边申请、边复盘。

### 只刷 LeetCode

项目、基础和 Behavioral 同样会决定面试结果。

### 每个岗位用完全相同的 CV

至少应该关注岗位对 Skill 和 Experience 的重点。

### 面试失败后不复盘

如果每次都不知道为什么失败，很容易重复同样的问题。

### 无限增加项目数量

大三后项目深度通常比单纯数量更重要。

---

## 大三结束 Checklist

- [ ] CV 已达到正式投递状态
- [ ] 有 2–4 个核心项目
- [ ] 每个核心项目都能 Deep Dive
- [ ] LeetCode 常见 Pattern 已覆盖
- [ ] 能解释常见 CS 基础问题
- [ ] 有 Behavioral STAR 故事库
- [ ] 有长期 Job Tracker
- [ ] 经历过真实 OA 或面试
- [ ] 每次面试后会复盘
- [ ] 对目标岗位越来越明确
