# 大二应该做什么

> 大二最重要的变化，是从“会写代码”进入“会构建软件”。

如果说大一主要是在打基础，那么大二应该开始形成自己的技术主线。

这一年通常是很多学生差距真正开始拉开的阶段。

```text
课程基础
→ 技术方向
→ 工程项目
→ CV
→ Internship 准备
```

---

## 大二结束时，你应该达到什么状态

比较理想的状态是：

- 有一个主要技术方向
- 有 1–2 个能够认真讲解的项目
- GitHub 不再只有课程作业
- 已经有第一版 CV
- 开始系统做 LeetCode
- 开始关注 Internship 招聘
- 能够解释自己项目中的技术选择

---

## 第一件事：开始形成主技术方向

你不需要永远绑定一个方向。

但从大二开始，最好不要每个月换一次技术栈。

### Backend 路线示例

```text
Java
→ Spring Boot
→ REST API
→ MySQL / PostgreSQL
→ Redis
→ Testing
→ Docker
```

### AI 路线示例

```text
Python
→ NumPy / Pandas
→ Machine Learning
→ PyTorch
→ Evaluation
→ Model Serving
```

### Frontend 路线示例

```text
JavaScript / TypeScript
→ HTML / CSS
→ React / Vue
→ API Integration
→ State Management
→ Testing
```

选择方向时可以问自己：

1. 我愿不愿意长期学这个？
2. 我有没有相关课程或项目？
3. 我能不能在未来半年做出作品？
4. 这个方向和我的求职目标是否一致？

---

## 第二件事：开始补 CS 核心基础

这一阶段常见的重要基础包括：

- Data Structures & Algorithms
- Database
- Operating Systems
- Computer Networks
- Software Engineering
- Object-Oriented Design

不要把这些课理解成“考试结束就没用了”。

这些内容以后会不断出现在：

- Technical Interview
- System Design
- Backend
- Debugging
- Performance Analysis

例如学习 Database 时，不只要知道 SQL 怎么写。

还应该逐渐理解：

- Index 是什么
- Transaction 是什么
- Primary Key / Foreign Key
- JOIN
- Normalization
- 为什么查询会慢

---

## 第三件事：项目开始工程化

大二项目和大一项目最大的区别，不是代码量。

而是项目开始出现工程结构。

例如一个 Backend 项目可以逐渐加入：

- Authentication
- REST API
- Database
- Validation
- Error Handling
- Logging
- Testing
- Docker
- Deployment

你开始需要解释：

> 为什么这里需要数据库？
>
> 为什么选择 Redis？
>
> Authentication 怎么实现？
>
> 如果服务出错怎么处理？

这才是从 Tutorial Project 走向 Engineering Project。

---

## 第四件事：做第一版真正的 CV

大二就应该写 CV。

即使你还没有实习，也可以先建立结构。

常见模块：

```text
Education
Experience
Projects
Technical Skills
```

项目描述不要只写技术名词。

弱表达：

> Used Java, MySQL and Redis.

更好的方向是：

> Built a REST API for ... using Java and Spring Boot, with MySQL for persistent storage and Redis for ...

重点是说明：

- 做了什么
- 为什么
- 用了什么
- 产生什么结果

## 第五件事：开始认真准备 Internship

不同国家、公司和年份的 Internship 招聘时间不同。

具体 Deadline 应以公司官方 Career Page 为准。

但能力准备最好不要等岗位开放以后才开始。

你应该提前知道典型流程：

```text
Application
→ Resume Screening
→ OA
→ Technical Interview
→ Behavioral Interview
→ Offer
```

### 建立 Job Tracker

最简单可以记录：

| Company | Role | Date | Status | Next Step |
| --- | --- | --- | --- | --- |
| Example | Software Intern | 2026-xx-xx | Applied | OA |

不要只依赖浏览器收藏夹。

---

## 第六件事：LeetCode 进入系统阶段

大二可以逐渐覆盖：

- Array
- String
- HashMap
- Two Pointers
- Sliding Window
- Stack
- Queue
- Linked List
- Binary Search
- Tree
- Heap
- DFS / BFS 基础

建议开始建立自己的题型笔记。

每道代表题至少记录：

- Pattern
- 核心思路
- 时间复杂度
- 容易犯的错

---

## 第七件事：开始练习讲项目

很多学生项目写得不错，但不会讲。

可以先用这个结构：

```text
项目背景
→ 我负责什么
→ 技术架构
→ 最大挑战
→ 如何解决
→ 最终结果
```

如果一个项目只能说：

> “这是我们课程要求做的。”

那么它还没有真正转化成你的求职资产。

---

## 大二如何安排优先级

一个比较健康的顺序是：

```text
课程不崩
   ↓
技术主线稳定
   ↓
完成核心项目
   ↓
建立 CV
   ↓
持续 LeetCode
   ↓
开始 Internship 申请
```

不是所有事情每天都需要做。

但这些事情最好在一年内逐渐连起来。

---

## 大二最常见的错误

### 一直停留在课程项目

课程项目可以使用，但最好逐渐增加个人独立决策。

### 技术栈频繁重启

今天 Java，明天 AI，后天 Web3，很容易导致每条路线都很浅。

### CV 等到申请当天才写

CV 本身需要不断迭代。

### 觉得没有实习就不能投 Internship

第一份实习本来就意味着你可能没有之前的实习经历。

项目和基础能力同样重要。

### 只学框架不学基础

知道 Spring Boot 怎么启动，不等于理解 HTTP、Database 和 Backend。

## 大二结束 Checklist

- [ ] 已形成主要技术方向
- [ ] 有至少一个工程化项目
- [ ] 项目有完整 README
- [ ] GitHub 有持续维护记录
- [ ] CV 已经可以投递
- [ ] LeetCode 已系统覆盖基础题型
- [ ] 能讲清一个核心项目
- [ ] 已开始关注或申请 Internship
- [ ] 对常见招聘流程有基本了解
