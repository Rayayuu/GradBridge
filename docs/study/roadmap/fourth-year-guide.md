# 大四应该做什么

> 大四的核心任务不是“再多学一点”，而是完成从学生到职业工程师的转换。

到了最后一年，你会同时面对很多事情：

- Final-year courses
- Capstone
- Honours / Thesis
- Graduate Program
- Full-time Application
- Interview
- 毕业规划
- Visa / Location
- Master / PhD 选择

所以大四最重要的是优先级。

---

## 大四结束时，你真正需要的结果

理想情况下，你应该拥有：

- 明确的目标岗位
- 稳定版本的 CV
- 2–4 个能深入讲解的核心项目
- 比较成熟的面试能力
- 稳定维护的 Job Tracker
- 对 Graduate / Full-time 招聘节奏有认识
- 明确的 Plan A / Plan B

并且能够清楚回答：

> 我毕业后准备做什么？

---

## 第一件事：明确你的目标岗位

到了大四，求职方向最好已经比较明确。

例如：

- Software Engineer
- Backend Engineer
- AI Engineer
- Machine Learning Engineer
- Data Engineer
- Security Engineer
- Graduate Developer

不要再使用非常模糊的目标：

> “只要是 CS 工作都可以。”

方向越明确，你越容易决定：

- CV 放什么
- 项目强调什么
- 技术补什么
- 面试准备什么

---

## 第二件事：Graduate / Full-time 提前准备

很多 Graduate Program 的招聘周期可能早于毕业。

具体开放时间、Eligibility 和 Deadline 每年都可能变化。

因此实际申请时必须检查公司官方 Career Page。

但准备工作可以提前完成：

- CV
- Transcript
- GitHub
- LinkedIn
- Cover Letter 模板
- Behavioral 故事
- LeetCode
- Job Tracker

不要等 Deadline 前一天才整理。

---

## 第三件事：停止无限增加项目

大四常见误区之一，是觉得简历不够强，于是不断做新项目。

但到了这个阶段，很多时候更重要的是：

**把已有项目讲深。**

一个核心项目至少应该能回答：

- 项目解决什么问题？
- 架构是什么？
- 你负责什么？
- 最难的技术问题是什么？
- 为什么选择这个技术？
- 出现过什么失败？
- 怎么 Debug？
- 如何测试？
- 如何部署？
- 如果重新设计会改什么？

甚至可以继续思考：

> 如果用户从 100 人增长到 100 万人，会发生什么？

这就是项目开始接近 System Design 的地方。

---

## 第四件事：建立求职漏斗

大四不应该只看“投了多少份”。

应该看完整漏斗：

```text
Applications
     ↓
OA
     ↓
Interview
     ↓
Final Round
     ↓
Offer
```

不同位置的转化率，可以帮助你判断问题在哪里。

### Application → OA 很低

可能需要检查：

- CV
- 岗位匹配
- Eligibility
- 招聘时间

### OA → Interview 很低

可能需要检查：

- LeetCode
- Coding Speed
- Edge Cases
- Test Cases

### Interview → Offer 很低

可能需要检查：

- Technical Depth
- Project Explanation
- Behavioral
- Communication

这种分析比单纯“再投 100 家”更有价值。

---

## 第五件事：面试准备进入综合阶段

大四的面试准备应该逐渐整合。

### Coding

- 常见 Algorithm Pattern
- Complexity
- Edge Cases
- 清晰表达思路

### CS Fundamentals

- OOP
- Database
- OS
- Network
- Concurrency

### Engineering

- API
- Authentication
- Cache
- Testing
- Deployment
- Debugging

### Project

- Architecture
- Trade-off
- Challenge
- Impact

### Behavioral

- Leadership
- Conflict
- Failure
- Ownership
- Learning
- Collaboration

面试能力本质上是多个模块的组合。

---

## 第六件事：把 Capstone / Honours 转化成职业资产

Final-year Project、Capstone 或 Honours 不应该只在提交后结束。

可以继续整理成：

- GitHub Repository
- Technical README
- Architecture Diagram
- Portfolio Entry
- CV Bullet Points
- Interview Story

尤其需要明确：

> 哪些工作是你真正完成的？

团队项目里这一点非常重要。

---

## 第七件事：建立 Plan A 和 Plan B

毕业前最好不要只有一条路线。

例如：

### Plan A

Graduate Software Engineer

### Plan B

Internship / Junior Engineer / Contract Role

或者：

### Plan A

直接就业

### Plan B

继续 Master / Research

Plan B 的意义不是悲观。

而是避免某一个时间节点没有结果时完全失去方向。

---

## 第八件事：开始用工程师标准要求自己

学生时期常见判断标准是：

> “代码能运行。”

进入工作后，标准会逐渐变成：

- 可读吗？
- 可维护吗？
- 有测试吗？
- 出错怎么办？
- 能部署吗？
- 有日志吗？
- 安全吗？
- 能被别人接手吗？

因此最后一年应该逐渐改变自己的工程习惯。

---

## 大四每个月都值得检查的事情

### 求职

- 本月申请了什么？
- 哪些岗位进入下一轮？
- 哪个环节失败最多？

### 技术

- 当前最大技术短板是什么？
- 有没有真正影响面试的问题？

### 项目

- 核心项目能否深入讲解？
- README 是否完整？

### 面试

- 最近遇到什么不会的问题？
- 是否已经补上？

### 方向

- 目标岗位是否越来越清晰？

---

## 大四最常见的错误

### 等毕业后再找工作

很多招聘流程在毕业前就已经开始。

### 同时申请完全不同的岗位

如果 Backend、AI、Data、Product 全部使用同一套材料，往往很难突出匹配度。

### 只关注投递数量

投递多不代表求职流程健康。

### 项目越来越多，但都讲不深

最后一年应该优先强化深度。

### 没有 Plan B

求职具有不确定性，需要提前准备替代路径。

---

## 大四结束 Checklist

- [ ] 目标岗位已经明确
- [ ] CV 有稳定版本
- [ ] LinkedIn / GitHub 已整理
- [ ] 有 2–4 个核心项目
- [ ] 可以深入讲解项目架构和 Trade-off
- [ ] Coding Interview 有稳定准备体系
- [ ] CS Fundamentals 已系统复习
- [ ] Behavioral 故事库完整
- [ ] Job Tracker 持续维护
- [ ] 会根据求职漏斗定位问题
- [ ] 有 Plan A 和 Plan B

---

## 从学生到工程师

大学四年最终应该完成的，并不是把所有技术都学完。

没有人能够在毕业前学完计算机科学。

真正重要的是形成一套可以持续工作的能力系统：

```text
学习新技术
     +
理解基础
     +
构建项目
     +
解决问题
     +
清晰沟通
     +
持续迭代
```

当你拥有这套能力以后，毕业并不是学习结束。

而只是从：

**CS Student**

走向：

**Software Engineer**

的下一阶段。
