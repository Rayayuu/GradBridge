# 课程、项目与 LeetCode 怎么分配

> 三者都重要，但它们解决的是完全不同的问题。

很多 CS 学生会陷入一个循环：

```text
课程忙
→ 停止项目
→ 考完开始刷题
→ Assignment 又来了
→ 再次全部停止
```

问题不是你不努力。

而是没有给不同类型的成长建立固定位置。

---

## 三者分别解决什么问题

### 课程

主要建立：

- CS 基础
- 系统知识
- Academic Performance
- Structured Learning

### 项目

主要训练：

- Engineering
- Debugging
- Architecture
- Git
- Collaboration
- Delivery

### LeetCode

主要训练：

- Data Structures
- Algorithm Pattern
- Problem Solving
- Coding Interview

所以任何一个都无法完全替代其他两个。

---

## 大一的优先级

建议更偏向：

```text
课程基础
>
编程练习
>
小项目
>
基础 LeetCode
```

原因很简单：

如果连编程和数据结构都还不熟，过早大量刷题收益有限。

---

## 大二的优先级

逐渐变成：

```text
课程基础
+
工程项目
+
稳定 LeetCode
```

这一阶段最重要的是不要再只有 Coursework。

你需要开始留下真正属于自己的技术资产。

---

## 大三的优先级

如果进入招聘周期，通常需要提高求职相关投入。

例如：

```text
课程不崩
+
项目深挖
+
LeetCode
+
Interview
```

此时项目数量不一定需要继续增长。

更重要的是：

- 项目能不能讲
- 算法能不能写
- 基础能不能答

---

## 大四的优先级

最后一年通常更加岗位导向。

```text
毕业要求
+
目标岗位技术
+
面试
+
求职
```

不要因为觉得“还没学完”而无限推迟申请。

---

## 推荐使用固定时间块

相比“有空就做”，固定时间更稳定。

例如：

```text
平日
课程 + Assignment

每周固定两到三次
LeetCode

周末固定时间
Project

每周一次
Career Review
```

具体小时数并不重要。

重要的是长期不断线。

---

## 如何判断现在应该把时间加到哪里

看你的最短板。

### 成绩已经危险

优先课程。

### 成绩稳定，但没有项目

增加项目投入。

### 项目很多，但 OA 总挂

增加 LeetCode。

### OA 能过，但面试讲不清项目

减少新项目，开始 Deep Dive。

这比固定使用“40% / 30% / 30%”更有效。

---

## 不要把项目理解成额外负担

好的项目可以同时帮助你学习：

- Database
- Network
- Backend
- Testing
- Git
- Deployment

它本身也是学习方法。

---

## 不要把 LeetCode 理解成考试题库

如果只是记答案，很容易换一道题就不会。

更有效的是建立 Pattern。

```text
题目
→ 识别模式
→ 找到数据结构
→ 推导算法
→ 分析复杂度
```

---

## 一个实用的每周 Review

每周末只回答四个问题：

1. 这周课程最大的知识缺口是什么？
2. 项目推进了什么？
3. 新掌握了哪个算法 Pattern？
4. 下周最重要的一件事是什么？

这比每天重新规划整个大学生涯更有效。

---

## 最终原则

不要追求每天三项全部完成。

追求的是：

**整个学期里，课程、项目和算法都在持续向前。**
