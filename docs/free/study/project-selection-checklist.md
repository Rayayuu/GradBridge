# CS Project 选择 Checklist

项目不是越大越好。

真正值得投入的项目，应该同时满足：

> 能学到东西、能完成、能展示、能讲清楚。

## 开始前先问

- [ ] 这个项目解决什么具体问题？
- [ ] 谁会使用它？
- [ ] 最核心的 Feature 是什么？
- [ ] 两到六周内能不能做出 MVP？
- [ ] 是否需要真正的 Database / API / Model？
- [ ] 有没有可以量化的结果？
- [ ] 最后能不能部署或 Demo？

## 技术深度检查

- [ ] 有没有 Authentication / Authorization？
- [ ] 有没有 Database Design？
- [ ] 有没有 Error Handling？
- [ ] 有没有 Testing？
- [ ] 有没有性能或可靠性问题？
- [ ] 有没有真正做过技术取舍？

不需要全部满足。

但如果一个项目只是把 UI 页面拼出来，Technical Interview 可讲的内容通常有限。

## 求职价值检查

- [ ] 可以写成 2–3 条有信息量的 CV Bullet
- [ ] 可以解释 Architecture
- [ ] 可以解释一个困难 Bug
- [ ] 可以解释一个 Trade-off
- [ ] 可以解释你个人具体贡献
- [ ] GitHub README 能让陌生人快速理解

## 不太推荐的项目

- 完全照教程复制
- 只有静态 UI
- Scope 大到永远做不完
- 使用几十个技术但每个都只碰一点
- 无法解释自己做了什么

## 一个更好的项目描述

不要说：

> 做了一个电商网站。

而应该能说：

> 设计并实现一个带 JWT Authentication、PostgreSQL、Redis Cache 和 Docker Deployment 的电商 Backend，并针对商品查询路径减少重复数据库访问。
