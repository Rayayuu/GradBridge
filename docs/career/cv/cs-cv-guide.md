# CS CV 完整指南

一份好的技术 CV 不是“把经历全部放进去”。

它的目标是：

> 让招聘者在很短时间内理解你是谁、做过什么、会什么，以及为什么值得进入下一轮。

## 一页优先

对于大多数学生和 Early Career 候选人，一页通常更清晰。

常见结构：

1. Name + Contact
2. Education
3. Experience
4. Projects
5. Technical Skills

如果还没有正式 Experience，可以把 Projects 提前。

## Header

通常包括 Name、Email、Phone、LinkedIn、GitHub 和 Portfolio。

不要让 Header 占用太多垂直空间。

## Education

建议包括：

- University
- Degree
- Major
- Expected Graduation
- WAM / GPA（如果有竞争力）
- Relevant Coursework（必要时）

不要列十几门课程，只保留和目标岗位真正相关的内容。

## Experience

每段经历建议包含 Company、Role、Location、Date 和 2–4 个高质量 Bullet。

弱：

> Responsible for backend development.

更好：

> Implemented REST APIs for order workflows using Spring Boot and PostgreSQL, adding validation and error handling for core service endpoints.

如果有真实量化结果，再加入数字。不要为了数字而编数字。

## Project

每个核心 Project 至少应该回答：

1. 解决什么问题？
2. 你具体做了什么？
3. 使用什么技术？
4. 有什么技术难点？
5. 结果是什么？

## Technical Skills

可以按类别组织：

- Languages: Java, Python, JavaScript, SQL
- Backend: Spring Boot, Node.js, REST
- Database: PostgreSQL, MySQL, Redis
- Tools: Git, Docker, Linux

不要把 Microsoft Word、Internet、Hard-working 写进 Technical Skills。

## Skills 不要堆关键词

写在 CV 上意味着你应该能够接受追问。

如果写 Redis，至少应该理解为什么使用、TTL、常见数据结构、Persistence 基础和 Cache invalidation 的基本问题。

## Bullet 基本结构

**Action + Technical Detail + Result / Purpose**

例如：

> Built a FastAPI service that processed uploaded CSV files and generated structured analytics for dashboard visualization.

不是每个 Bullet 都必须有百分比。技术细节本身也能够提供可信度。

## CV 是否应该针对岗位调整

应该，但不需要每个岗位都重新写一份。

可以准备 Master CV，再根据 Backend、Software Engineering、AI / Data 等方向调整 Project、Skills 和 Bullet 顺序。

## ATS 基本原则

- 使用标准 Section Heading
- 避免复杂多栏布局
- 不依赖图标表达关键信息
- 不把重要文字放在图片中
- 使用岗位真实关键词
- 保持 PDF 文本可以选择

目标不是“骗过 ATS”，而是让机器和人都容易理解。

## 投递前 Checklist

- [ ] 一页为主
- [ ] Email 专业
- [ ] LinkedIn 正常打开
- [ ] GitHub 链接正确
- [ ] 日期格式一致
- [ ] Bullet 使用主动动词
- [ ] 没有明显拼写错误
- [ ] 技术栈与目标岗位匹配
- [ ] PDF 可以复制文字
- [ ] 文件名专业

## 最后

CV 不是你全部能力的完整记录，而是一个筛选工具。

优秀的 CV 不一定信息最多，而是能最快让招聘者看到：这个候选人做过相关的事，而且值得继续聊。
