# Project Bullet 怎么写

很多 CS 学生做过不错的项目，但 CV 上写出来以后非常普通。

问题通常不是项目太弱，而是 Bullet 只写了“做了什么”。

好的 Bullet 还应该让招聘者看到你怎么做、使用了什么技术、遇到了什么问题，以及产生了什么结果。

## 最常见的弱写法

> Developed a website using React.

问题是看不到产品类型、个人贡献、Backend、Database、技术难点和结果。

更完整的版本：

> Built a React and Node.js task management platform with JWT authentication and PostgreSQL persistence, implementing REST APIs for user and task workflows.

## 推荐结构

**Action + Scope + Technology + Technical Detail + Result**

不需要每一条都把五项全部塞进去，但每一条 Bullet 都应该提供新的信息。

## Action

常用动词包括 Built、Designed、Implemented、Developed、Integrated、Automated、Optimized、Refactored、Deployed、Tested 和 Led。

尽量少用 Worked on。

## Scope

告诉招聘者你真正负责的范围，例如：

- Authentication Flow
- REST API
- Recommendation Pipeline
- Database Schema
- CI Pipeline
- Data Processing Workflow
- Dashboard
- Model Training Pipeline

## Technical Detail

> Implemented JWT-based authentication with role-based authorization for protected API routes.

通常比“Added login functionality”更有信息量。

## Result

Result 不一定必须是百分比。

真实结果还可以是 reduced manual work、supported a workflow、improved reliability、passed tests、deployed successfully 或 processed a dataset。

只有真实测量过的数字才写数字。

## 三条 Bullet 如何分工

第一条写整体系统，第二条写技术难点，第三条写工程质量或结果。

例如 Backend 项目：

> Built a Spring Boot booking platform with PostgreSQL persistence and REST APIs for users, venues, and reservations.

> Implemented JWT authentication and role-based access control for customer and administrator workflows.

> Added validation, exception handling, and integration tests for core booking endpoints to improve API reliability.

## AI / ML 项目

不要只写 Trained a machine learning model。

至少说明 Data、Task、Model、Evaluation 和个人贡献。

## Group Project

不要只写 Worked with a team of five。

应该说明自己具体负责什么，以及如何与其他模块协作。

## 不要为了量化而造数字

如果没有真实 benchmark，不要写 Improved performance by 70%。

真实技术成果本身就有价值。

## 自检

问自己两个问题：

1. 如果删除技术名词，这句话还剩什么？
2. 面试官看到这句话以后，能不能产生具体追问？

好的 Bullet 应该自然产生“为什么这样设计”“怎么实现”“遇到什么问题”“Trade-off 是什么”等追问。

## 最后

Project Bullet 的目标不是让项目听起来很厉害，而是让招聘者相信你真的做过工程，而且理解自己做了什么。
