# Behavioral Interview 与 STAR Story Bank

Behavioral Interview 最常见的误区是等面试官问了以后现场想。

结果往往是故事太长、背景太多、自己做了什么不清楚，也没有明确结果。

更好的方式是提前建立自己的 Story Bank。

## STAR 是什么

### Situation

发生了什么？

### Task

你的责任是什么？

### Action

你具体做了什么？

### Result

最后结果如何？

其中最重要的通常是 Action，因为面试官真正想知道的是你做了什么。

## 不要全部使用 We

团队背景可以使用 We，但 Action 部分需要明确说明：

- I proposed
- I implemented
- I coordinated
- I debugged
- I communicated

## 建议准备的故事类型

- Leadership
- Conflict
- Failure
- Tight Deadline
- Difficult Technical Problem
- Learning Something Quickly
- Team Collaboration
- Ownership
- Ambiguous Requirement
- Receiving Feedback

一个故事可以回答多个问题，但回答角度应该根据问题调整。

## Leadership 不等于当组长

Leadership 可以表现为主动推动任务、明确分工、解决阻塞、帮助团队决策、改进流程和承担责任。

## Conflict 怎么讲

不要把别人描述成很差。

更成熟的结构是说明双方目标、分歧、如何理解对方、如何沟通验证，以及最后如何推进。

## Failure 怎么讲

不要使用“我太追求完美”这种伪缺点。

更好的 Failure Story 应包含真实错误、影响、责任、修复方式以及后来改变了什么。

## Technical Challenge

软件工程候选人最好准备至少一个真实技术难题，例如难查 Bug、性能问题、API Integration、Deployment 或 Data Issue。

它可以同时体现 Technical Skill、Ownership、Communication 和 Persistence。

## Story Bank 怎么整理

| Story | Leadership | Conflict | Failure | Technical |
| --- | --- | --- | --- | --- |
| API redesign | ✓ | ✓ |  | ✓ |
| Internship bug |  |  | ✓ | ✓ |
| Hackathon deadline | ✓ |  |  | ✓ |

面试前不需要背整段英文，而是熟悉每一个故事的关键节点。

## Result 没有数字怎么办

真实 Result 可以是 project delivered on time、bug resolved、team adopted the proposal、client accepted the output 或 improved collaboration。

不要为了显得厉害而编造百分比。

## Why this company

可以从公司或产品、目标岗位、个人经历连接，以及希望获得的成长四个部分准备。

不要只回答 Because your company is famous。

## Tell me about yourself

建议形成一个简洁职业叙事：现在是谁、主要技术方向、相关经历、为什么正在寻找这个岗位。

不需要从高中开始讲。

## 面试前 Checklist

- [ ] 6–10 个真实故事
- [ ] 每个故事都有明确 Action
- [ ] 能说清 Result
- [ ] 能说出 Learning
- [ ] 准备 Why Company
- [ ] 准备 Why Role
- [ ] 准备 Tell Me About Yourself
- [ ] 用英文实际说过至少一遍

## 最后

Behavioral Interview 在判断一个人进入真实团队以后，会怎么沟通、承担责任、处理冲突、学习和交付。

最有效的准备方式不是背模板，而是把真实经历整理成清楚、可信、可追问的故事。
